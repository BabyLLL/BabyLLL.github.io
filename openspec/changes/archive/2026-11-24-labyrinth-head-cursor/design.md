# Design

## Context

Both skins are generated by `tools/make-skins.py`; the current head painter gives BabyLLL short hair with a square-sunglasses band and Xiaoguai long hair (hat layer) with cat-eye sunglasses and red lips. The reference site (Labyrinth) publishes its skin at `assets/me.png` — 64x64 — showing the adopted head: full black hair (all four side faces + top) with faint shade variation and two white sparkle pixels near the crown, a cute face of white eye blocks with dark pupils over skin, and a small pink mouth row. Its cursor is a 32x32 diamond-sword PNG applied through a `--sword-cursor` CSS variable.

## Goals / Non-Goals

- Goals: the reference character wholesale on both skins (head and body); the sword cursor site-wide; no engine modifications.
- Non-Goals: changing the engine's dynamic canvas cursors; other Labyrinth features (agent chat, weather, dock apps).

## Decisions

- **Start each skin from the reference skin as base, repaint only the head.** (Updated mid-implementation on user request: "身体也替换吧" extended the swap to the body.) All overlay layers are cleared and the head painter runs on top, so both characters wear the reference outfit exactly — black tee, dark jeans, white shoes — with our head style. The reference base is vendored to `tools/labyrinth-base.png`. Reference measurements read off their skin: hair fringe covers the top two face rows plus temples; eyes are two 1x2-ish white blocks with a dark pupil pixel on the eye row; mouth a 2px soft-pink row; sparkles sit on the top face near the front.
- **Both characters share the new head; differentiation stays on hair shape and accents.** BabyLLL keeps a hat-layer volume crop (short style); Xiaoguai keeps her full hat-layer long hair and gold earring. Sunglasses and red lips go — the reference design has neither, and at 8x8 they were the weakest part of the previous design. (Assumption recorded: user asked "只替换头部" — wholesale head adoption for both; keeping the sunglasses would contradict the reference style.)
- **Cursor CSS mirrors the reference site's own rules**, adapted to our selectors: `--sword-cursor: url(...sword.png) 0 0` on a root variable; `html, body, #world, #world canvas, dialog` get `var(--sword-cursor), auto`; HUD/panel buttons, links, minimap and phone apps get `var(--sword-cursor), pointer`. The engine sets canvas cursor inline (hidden while web-aiming, pointer over the portal) — inline styles beat the stylesheet, so those affordances survive untouched; only the pointer-over-portal differs from the reference (ours stays pointer, theirs forces the sword). Accepted: pointer there is the correct affordance.
- **Cursor asset ships in `public/assets/cursor/sword.png`** (copied verbatim from the reference site, 32x32 RGBA — inside every browser's cursor size cap). Applied from a new `src/cursor.css` imported by `src/main.js`, so it lands after `engine/style.css` and wins on equal specificity without touching engine files.

## Risks / Trade-offs

- [Sword image may fail to load] → CSS fallbacks (`auto`/`pointer`) keep the site usable; asset is local and tiny.
- [Two characters now deliberately wear matching outfits] → per user instruction; hair length (short crop vs long fall) + earring keep them distinguishable; a palette variant for Xiaoguai can be a follow-up if wanted.
- [Sparkle pixels read as noise at distance] → only two white pixels on the crown, matching the reference; accepted.

## Migration Plan

Pure asset/CSS change; rollback = revert the three touched files. No data or API changes.
